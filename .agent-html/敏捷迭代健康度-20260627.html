评分标准 2026

满分 100 分
迭代过程管理40 分
需求梳理和宣讲15分
需求方案前置一个迭代就绪；描述规范、有业务背景/流程/功能点；充分澄清拆分（PSPS）；三方评审（需求梳理会）；宣讲会按时高效召开
检查：全检+抽查 · 迭代开始前周五
迭代计划和开发15分
设计方案输出与评审；任务拆分有明确计划完成时间；每日晨/晚会进展对称；代码审查例行开展；测试用例输出评审；迭代测试报告（含结论和缺陷分析）
检查：抽查 · 迭代开发第二天
迭代演示和回顾10分
需求通过验收、演示顺畅（有剧本和数据准备、无明显低级Bug）；回顾会有清晰改进目标和措施且有明显效果
检查：抽查 · 迭代后第二天
▶ 评分规则详情
需求梳理评分规则

① 需求总量 < 80%团队总量 → 扣5分
② 需求描述缺少业务背景/流程/功能点说明/界面说明/标准工时 → 缺少每项扣1~5分
③ 无评审记录 → 执行情况得分扣2分
标准会议活动未执行 → 整项不得分；抽查小项不满足 → 单项扣3分

迭代计划评分规则

① 云效中需求未拆分 → 扣5分；部分未拆 → 扣3分
② 测试用例缺少一个 → 扣1分
③ 迭代报告缺少 → 扣5分；质量不高 → 扣1~3分
标准会议未执行 → 整项不得分；单项不满足 → 扣3分

演示回顾评分规则

① 演示/回顾会议未召开（无记录上传）→ 整项不得分
② 改进和坚持事项不明确 → 质量不高扣1~5分
抽查小项不满足 → 扣5分
