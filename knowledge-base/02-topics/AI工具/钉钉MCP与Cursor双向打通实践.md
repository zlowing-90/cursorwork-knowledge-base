# 钉钉 MCP 与 Cursor 双向打通实践

> **核心结论**：通过 4 步零代码配置钉钉 MCP，即可让 Cursor AI 用自然语言双向读写钉钉文档与表格，彻底消除"钉钉 ↔ Cursor"之间的人工复制粘贴。

**提炼方法**：金字塔原理——先给结论，再用 3 个支撑论点（为什么做 → 怎么配置 → 能做什么）展开，MECE 无重叠、无遗漏。

---

## 一、为什么要做（价值与痛点）

| 痛点 | 目标 |
|------|------|
| 钉钉文档无法直接被 Cursor AI 读取 | Cursor 能直接读取、检索钉钉文档内容 |
| Cursor 产出物（PRD/方案）需手动复制回钉钉 | Cursor 产出内容能自动上传回钉钉 |
| 信息孤岛：两端知识无法沉淀复用 | 钉钉知识定期扫描沉淀进 AI 上下文 |

**本质**：打破「钉钉存文档，Cursor 写代码/分析」的信息孤岛，实现双向流动的 AI 增强工作流。

---

## 二、怎么配置（4 步零代码）

```
第 1 步  打开钉钉 MCP 集市  →  https://aihub.dingtalk.com/
第 2 步  分别开通 3 个 MCP（钉钉文档 / 钉钉表格 / 钉钉文档互动服务）
         → 每个 MCP 详情页复制你的专属 streamable-http URL
第 3 步  在 Cursor 对话框粘贴 URL，告诉 AI：
         "帮我注册这三个 MCP，名称分别叫
          dingtalk-doc、dingtalk-spreadsheet、dingtalk-doc-comment"
         → AI 自动写入 ~/.cursor/mcp.json
第 4 步  Ctrl+Shift+P → Developer: Reload Window  让配置生效
```

**验证方法**：随便发一条"帮我读 `<钉钉文档URL>` 内容，按章节摘要"，AI 能返回标题和要点即成功。

> ⚠️ **安全注意**：每人的 key 等同登录凭证，**不要转发给同事**；团队成员需各自从 MCP 集市自助开通。

## 三、能做什么（典型能力全景）

### 3.1 钉钉文档（读取 + 分析 + 生成 + 回写）

| 场景类型 | 典型 Prompt 示例 |
|----------|-----------------|
| 读取分析 | "读这份客户调研纪要，按业务领域归类需求条目" |
| 版本对比 | "对比 PRD v1.0 和 v1.1，输出变更点清单" |
| 全库检索 | "在 MBM 产品知识库下找跟'装配管理'相关的所有文档" |
| 整理生成 | "把会议录音转写整理成 议题/决议/待办 三段" |
| 追加写入 | "把这次会议纪要追加到周会纪要 URL 末尾" |
| 内容替换 | "把 PRD 里'装配管理'章节替换为以下内容：……" |
| 文档搬迁 | "把草稿移动到'已归档'文件夹并重命名" |

### 3.2 钉钉表格（读取 + 筛选 + 更新 + 批量操作）

| 场景类型 | 典型 Prompt 示例 |
|----------|-----------------|
| 条件筛选 | "列出 责任人=刘一 且 计划完成≤5/15 的所有任务" |
| 汇总统计 | "按责任人统计每人的未完成任务数" |
| 批量修改 | "把状态='待执行'的行批量改为'执行中'" |
| 追加数据 | "在任务清单末尾追加一行：[责任人, 任务名, 日期, 状态]" |
| 格式调整 | "把 B 列数字格式改成百分比" |

### 3.3 钉钉文档互动服务（评论读写）

- 列出文档内所有未解决的评论
- 创建全文评论 / 划词评论，并 @相关同事
- 回复指定评论
