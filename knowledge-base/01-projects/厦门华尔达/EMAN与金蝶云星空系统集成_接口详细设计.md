# **详细设计**

## [进度: 已完成]**【01】人力档案（**ERP-\>EMAN**）**

---

| 维度 | 说明 |
|------|------|
| 接口规划 | 人力档案在ERP系统维护，通过接口将ERP系统人力基础档案传输至EMAN，以保持两个系统人力档案一致性 |
| 数据流向 | ERP-\>EMAN |
| 同步数据来源 | 本接口需同步的数据来源于ERP系统人力基础档案中部分人力信息，具体哪些人员需要传输至EMAN，此项在ERP系统进行定义。<br><span style="background-color: #F9DDB2;">计划实现方案</span>：ERP系统岗位信息需增加字段“可操作系统”，下拉选择系统名称，可按人员配置需要操作哪些系统，ERP只需传输 可操作系统 包含EMAN的人力档案至EMAN。 |
| 接口规则说明 | <ul><li>1. 本接口所关联的「部门」基础资料尚未通过接口集成，通过接口新增人力信息时，部门默认为“未定义”，后续由业务用户手动在EMAN系统更新员工所属部门，不支持通过接口更新部门；--需提前在EMAN建立名称为“未定义”的部门</li><br><span style="color: #FE0300;">【背景说明】：ERP系统中部门划分比较粗，业务用户需在EMAN系统中进行部门细分</span><br><li>2. 本接口所关联的「职务」基础资料尚未通过接口集成，通过接口新增人力信息时，职务默认为“未定义”，后续由业务用户手动在EMAN系统更新职务信息，不支持通过接口更新职务。--需提前在EMAN建立名称为“未定义”的职务</li><br><span style="color: #FE0300;">【背景说明】：两个系统职务基础档案不统一，且EMAN系统职务信息未关联业务。</span><br><li>3. 本接口只支持人力新增/修改，不支持删除，EMAN接收数据时基于自身系统业务逻辑判断是否允许执行对应操作，允许则通过接口执行，不允许则需给出错误提示，需业务用户手动干预处理。</li><br><div style="background-color:#FFFFFF"><li>1. 新增：EMAN接收数据基于系统限定必填而接口未传输的字段自动取默认值。</li><li>2. 修改：仅需基于接口约定字段进行更新，非接口约定字段不需覆盖更新。注：员工所属部门及职务不需通过接口更新</li><li>3. 删除：不支持删除，只支持禁用。ERP人力信息禁用后需按“离职”状态传输至EMAN</li></div><br><li>4. 接口需传输的关键字段包含：<span style="color: #ED7D33;">部门编码</span>、员工编号、<span style="color: ;">员工姓名、邮箱、在职状态</span>，约定使用员工编号作为数据唯一标识，EMAN基于此字段判断新增/修改；登录账号默认同员工编号一致。</li></ul> |
| 期初数据处理 | 接口上线前，将ERP系统已有的人力档案通过Excel方式导入EMAN |
| 接口调用说明 | <ul><li>1. 对接形式：ERP调用EMAN提供的API接口写入数据</li><br><li>2. 触发时机：接口需支持定时触发和手动触发</li><br><li style="margin-left:1em">1. 实时触发：1️⃣ ERP系统人力档案审核时触发新增/修改同步 2️⃣ ERP系统人力档案禁用/反禁用时同步在职状态</li><br><li style="margin-left:1em">2. 手动触发：同步失败的数据需支持在ERP系统手动触发再次同步</li><br><li>3. 分批策略：单次传输一条人力信息</li><br><li>4. 调用链路：新增和修改均调用同一个接口进行传输，通过员工编号识别新增/修改。</li><br><li>5. <span style="color: rgba(0, 0, 0, 0.85);">重试机制：ERP系统需接收EMAN返回的错误信息（如网络超时、数据校验失败），同步失败的数据支持在ERP系统手动重试同步；</span></li><br><li>6. <span style="color: rgba(0, 0, 0, 0.85);">日志记录：EMAN 系统记录接口调用日志（含请求参数、处理结果、时间），可在【系统管理-日志管理-接口日志】页面查询。ERP系统也需记录推送日志。</span></li></ul> |
| 接口字段定义 | 详见接口定义书【01 人力档案（ERP-\>EMAN）】，路径：https://www.kdocs.cn/l/caIYi724yl1G |

## [进度: 已完成]**【02】物料档案（**EMAN-\>ERP**）**

| 维度 | 说明 |
|------|------|
| 接口规划 | 业务用户在EMAN系统维护物料档案（模具材料、模具配件、模具成品），通过接口将EMAN系统物料档案传输至ERP，以保持两个系统物料档案一致性。 |
| 数据流向 | EMAN-\>ERP |
| 业务场景 | <ul><li>1. **标准件、原材料、非标件物料（由模具部负责创建）：**对应EMAN系统物料名称直属上级物料类型“是否成品”属性为“否”的物料</li><br><div style="background-color:#FFFFFF"><li>1. 标准件（标准物料号为 “是”，非标件为 “否”）：按 “物料名称 \+ 规格” 单独设料号，一规格对应唯一料号。</li><li>2. 非标件（标准物料号为 “是”，非标件为 “是”）：按物料名称定义通用料号，材质设为 “附图采购”、规格默认，实际规格在 BOM 中录入。</li><li>3. 原材料（标准物料号为 “否”）：按 “物料名称 \+ 材质” 定义料号；因企业财务核算需按规格区间区分料号，同一物料同一材质按规格区间最多设两个料号，故规格区间需体现在物料名称中。</li></div><br><li>2. **成品物料编码（由业务部负责创建）：**对应EMAN系统物料名称直属上级物料类型“是否成品”属性为“是”的物料</li><br><div style="background-color:#FFFFFF"><li>1. 业务流程： 意向订单报价转正式订单  -\> 下发开模通知单 -\>业务部创建模具成品料号基础档案 -\> 创建/下发模具订单 -\> 模具订单传输至ERP -\>ERP生成销售订单 -\> 提交/审核。</li><li>2. 意向订单报价阶段暂无模具编号，转正式订单时下发开模通知单，由业务部创建成品物料基础档案（物料编码对应模具编号，物料名称对应模具名称），在创建成品物料基础档案时还需维护模具类型及旧模具编号（兼容历史数据）。</li></ul></div> |
| 同步数据来源 | 本接口需同步的数据来源于EMAN系统【基础信息-物料数据-物料数据维护】页面所有物料数据<br>![image.png](https://alidocs2.oss-cn-zhangjiakou.aliyuncs.com/res/mPdnpEb4GrLVAqw9/img/33ce161f-fc4a-4ecd-940e-12f091865208.png?Expires=1783075119&OSSAccessKeyId=LTAI5tKTjg4Kq1HCdBJ8qpSp&Signature=dZYZ5yFJ6qgZ4pF%2Bss95fkQiVRc%3D "") |
| 关联基础档案 | 本接口关联的如下基础资料未通过接口对接，采取如下方式处理：<span style="color: #BB2626;">--接口上线前需提前完成相关信息录入</span><br><div style="background-color:#FFFFFF"><ul><li>1. **物料分类**：需线下保持两个系统物料分组一致，可使用EMAN系统物料类型“ERP类型编码”字段维护ERP物料分组编码。 --注：需基于物料名称<span style="color: #BB2626;">直属上级</span>物料类型维护ERP类型编码。</li>![image.png](https://alidocs2.oss-cn-zhangjiakou.aliyuncs.com/res/mPdnpEb4GrLVAqw9/img/d64edfc1-dc9f-4778-b67c-da0ac6e19ed8.png?Expires=1783075119&OSSAccessKeyId=LTAI5tKTjg4Kq1HCdBJ8qpSp&Signature=u2btJjFepexyYknohSSyLCWjZ6w%3D "")<li>2. **计量单位**：需线下保持两个系统计量单位一致，可使用EMAN系统“计量单位编号”维护“ERP计量单位编码”。</li><li>3. **仓库信息**：需线下保持两个系统仓库编码一致，可使用EMAN系统“仓库编码”维护“ERP仓库编码”。</li></ul></div> |
| 接口规则说明 | <ul><li>1. **接口功能限定**：本接口支持物料新增/修改，不支持删除，存在删除业务时，采取停用的方式处理（对应ERP的禁用）</li><br><div style="background-color:#FFFFFF"><li>1. 新增：物料信息成功同步至ERP系统时，EMAN需存储ERP返回的主键ID，便于后续进行数据追溯。</li><li>2.
